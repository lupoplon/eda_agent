# EDA с памятью

Локальное приложение для знакомства с CSV-данными, проверки их качества и повторяемой подготовки. Пользователь описывает таблицы и поля в чате, задает правила очистки и соединения. Агент сохраняет правила между сессиями и применяет их к выбранной версии данных.

## Запуск

Нужны Python 3.11+ и make.

~~~bash
cp .env.example .env
# Укажите GIGACHAT_CLOUD_KEY в .env
make run
~~~

Откройте http://localhost:8501. Первый запуск создает .venv и устанавливает зависимости. Используется GigaChat через Cloud.ru. Без ключа доступны локальные команды; понимание свободного текста и семантические эмбеддинги отключены.

Настройки в .env: GIGACHAT_CLOUD_KEY, GIGACHAT_MODEL, GIGACHAT_CLOUD_EMBEDDING_MODEL, CONTEXT_TOKEN_BUDGET. Значения по умолчанию приведены в .env.example. Файл с ключом не включается в Git.

## Работа с данными

1. Нажмите **«Загрузить новую версию»**. В одной форме укажите название и выберите CSV или встроенный пример. Нажмите **«Сохранить и использовать»**.
2. Опишите таблицы и задайте правила в чате. Справа отображаются сохраненные записи, их версии и сроки хранения.
3. Выполните /run 2026-06-30 или попросите применить преобразования обычной фразой.
4. Над таблицами появится отчет: одна строка на правило, применено/пропущено, причина и результат. Подготовленные CSV и manifest.json можно скачать.
5. Для следующей выгрузки через ту же кнопку создайте новую версию. Сохраненные версии выбираются в поле **«Версия данных для /run»**.

Каждая версия — полный неизменяемый набор таблиц. Имя CSV определяет имя таблицы. Новая загрузка не подмешивает прежние файлы; одинаковое название версии не допускается. Исходные версии сохраняются в SQLite, результаты — отдельно в data/output/<id_версии>/. Последняя выбранная версия восстанавливается после перезапуска.

Поддержаны удаление строк с пропусками, дедупликация, заполнение пропусков и left/inner join с проверкой кардинальности. Произвольный сгенерированный Python или SQL не исполняется.

## Примеры сообщений

> applications — заявки. application_id — ключ, customer_id — клиент. DECISION: 0 — отказ, 1 — одобрено без выдачи, 2 — выдано. Сохрани описание без преобразований.

> Сохрани правило 01_applications: удалить строки без application_id, оставить последнюю строку по application_id, пустой region заполнить UNKNOWN.

> Сколько записей в applications с пустым application_id?

> Примени сохраненные правила к выбранной версии на дату 2026-06-30.

> А после очистки сколько строк с пустым application_id?

Численные ответы рассчитываются pandas по исходным или подготовленным таблицам. Если таблица или поле неоднозначны, агент просит уточнение. Ответы о смысле данных подкрепляются сохраненными источниками; без определения агент сообщает, что ответа нет.

## Встроенные примеры

В форме загрузки доступны июньская и июльская поставки кредитного портфеля: applications, loans, monthly. В июле — 125/75/225 исходных строк, из них ровно 20% — лишние дубли ключей. После очистки остаются 100/60/180 строк.

В блоке «Как попробовать» можно скачать commands.txt. Первые пять строк отправляются в чат по одной: они задают описания и обработку примера. application_funnel включает все статусы заявок DECISION=0, 1 и 2.

## Память, контекст и диагностика

Правила и описания имеют id, редакцию, дату начала действия и источник. Дата /run выбирает редакцию правил, а не фильтрует месячные строки. Повторная обработка переиспользует готовые промежуточные результаты, только если правила и входные данные совпадают. Изменившиеся и зависимые правила выполняются заново. Промежуточный кэш хранится в RAM.

Сверху показаны оценка рабочего контекста и фактические входные/выходные токены API. При пороге около 8000 токенов появляется уведомление, история сжимается в резюме, старые сообщения убираются из текущего состояния агента. Правила и слоты сохраняются. Расход API не является порогом суммаризации; оценка размера контекста до отправки не заменяет точный токенизатор.

В боковой панели доступны запросы/ответы GigaChat, инструменты и Python-ошибки. Ключ маскируется; журнал может содержать данные пользователя. Приложение рассчитано на одного локального пользователя.

«Новый чат» сохраняет данные и правила. «С чистого листа» удаляет правила, версии данных, результаты и локальную историю. Автоматического TTL и фоновой переработки памяти пока нет.

## Код

- agent.py — граф диалога, GigaChat, память, поиск, версии данных, статистика и преобразования.
- app.py — Streamlit-интерфейс: загрузка, выбор версии, чат, таблицы, память и журнал.
- examples/credit_portfolio — CSV встроенных примеров и команды подготовки.
- Makefile, requirements.txt, .env.example — запуск и настройки.
